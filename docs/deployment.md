# Deploy the portfolio demo for two weeks

The configuration uses only free plans. Check the providers' current quotas before creating resources:

- [Vercel Hobby](https://vercel.com/docs/plans/hobby): personal, noncommercial projects.
- [Render Free](https://render.com/docs/free): idle sleep, resource limits, and a database that expires 30 days after creation.
- [Render Blueprint specification](https://render.com/docs/blueprint-spec).

## 1. Frontend project

Import drowningFi5h/hackThePlot into Vercel. Set the root directory to frontend and Node.js to 22. The build and install commands are in vercel.json.

Reserve the production URL. Set FRONTEND_URL to its exact HTTPS origin, with no trailing slash. Set BACKEND_URL after Render creates the API. Keep these variables server-side; do not prefix them NEXT_PUBLIC.

Preview deployments are intentionally not trusted automatically. Add an exact preview origin on both sides only when you intend to test it.

## 2. Backend and database

Create a Render Blueprint from the repository. The committed render.yaml explicitly requests a free web service and free PostgreSQL 16 database in Singapore. Do not accept paid substitutions.

Set:

| Variable | Value |
| --- | --- |
| FRONTEND_URL | Exact Vercel production HTTPS origin |
| CSRF_TRUSTED_ORIGINS | The same origin |
| DJANGO_SECRET_KEY | Generated by Render; retain securely |
| CERTIFICATE_SIGNING_KEY | Separately generated by Render |
| BOOTSTRAP_ADMIN_EMAIL | Your private organizer email |
| BOOTSTRAP_ADMIN_PASSWORD | A unique random password of at least 16 characters |
| DEMO_MODE | 1 for this portfolio demo; 0 for a real event |

DATABASE_URL is linked to the private Render database connection. TLS is required. The backend hostname is automatically included in Django's allowed hosts.

The public demo does not create an organizer by default. If you need organizer access, add the optional bootstrap variables yourself before the first deployment. Start-up applies migrations and creates that organizer only if absent. Remove both bootstrap variables after it is created. The backend health check is /health/ready/.

DEMO_MODE=1 seeds three synthetic challenges only on a fresh database. Each visitor gets a participant account with no usable password. Guest creation has a global limit of 30 per minute and 500 total accounts. Existing guest sessions retain their progress. No public organizer credentials are seeded.

## 3. Connect and verify

Set BACKEND_URL in Vercel to the Render HTTPS URL and redeploy the frontend. Use the exact Vercel URL configured in FRONTEND_URL.

Verify:

1. Health/readiness is green.
2. Try the demo creates a guest, and all three challenges can be solved.
3. The next challenge stays locked until the current one is solved.
4. Rankings update, wrong flags fail, and logout invalidates the session.
5. Django admin accepts only your private credentials.
6. The API rejects cross-origin mutations and exposes no challenge flags.
7. No demo passwords or secrets appear in the public repository or frontend bundle.

The portfolio event initially lasts 14 days from first seed. Adjust its times in admin if the demonstration window changes.

## 4. Free-tier limits

Render sleeps after 15 idle minutes; waking can take about a minute. The frontend offers retry messaging. Do not send artificial keep-alive traffic.

The free database expires after 30 days and has no managed backups. Record its creation/expiry dates outside the app. Create it close to the demonstration date and export data before expiry.

Media remains on organizer-selected external HTTPS hosts. Render's filesystem is ephemeral. No email service or SMTP dependency is required.

Do not add a payment method or upgrade resources automatically. Check provider usage dashboards before sharing the demo broadly. Local load results do not establish free-host capacity.

## 5. Updates and shutdown

Auto-deploy is disabled for the backend. Apply a tested release manually, after a backup. Revert the application release if needed; do not blindly roll back database migrations. This initial release has only additive migrations.

After two weeks, export standings/certificates and take a final encrypted backup. Remove the deployment when no longer needed. Certificate URLs require the backend; preserve verification exports if they matter.

The README should list a live URL only after the deployed frontend/backend have been verified together.
